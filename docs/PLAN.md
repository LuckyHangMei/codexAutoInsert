# Codex 自动续发工具开发计划

日期：2026-09-19（需求确认）；2026-09-20（交付）

状态：1.1 已完成，新增已有共享会话绑定。106 项断言及真实桌面联跑通过。原第一版范围保留作记录，追加范围见第 11 节。

## 1. 已确认的范围

做一个 Windows 独立桌面小工具。由工具启动 Codex，只管理一个会话。输出和手动输入都在工具窗口内完成。

只有当前回合最终失败，且失败原因匹配下列提示时，才按设置等待并自动发送用户填写的内容：

> We're currently experiencing high demand, which may cause temporary errors

| 项目 | 已确认要求 |
| --- | --- |
| 启动 | 窗口中选择工作目录，启动新的 Codex 会话 |
| Codex 配置 | 除工作目录外，沿用已有配置，不另设模型和推理强度选择 |
| 自动发送内容 | 窗口中填写，支持多行文本 |
| 触发时机 | 等本轮最终失败；Codex 内置重试期间不发送 |
| 等待策略 | 固定间隔、指数退避、自定义间隔序列 |
| 随机延迟 | 可选，在上述任一策略算出的间隔上附加范围内的随机延迟 |
| 自定义序列耗尽 | 持续使用最后一个间隔 |
| 连续次数上限 | 默认不限；允许设置上限；正常完成后重新计数 |
| 手动输入 | 运行中可以编辑，但必须先停止当前回合再发送；手动发送取消待发自动任务 |
| 后台行为 | 不切换其他窗口，不抢焦点，不读写剪贴板；最小化后继续工作 |
| 关闭窗口 | 退出工具，停止本工具启动的 Codex；不影响其他 Codex 进程 |
| 设置保存 | 记住目录、发送内容、策略及其参数；重新打开工具时自动发送默认关闭 |
| 会话恢复 | 每次启动新会话，不恢复旧会话或旧倒计时 |

第一版不接管既有 Windows Terminal 页签，不做多会话管理。交互范围是文本对话、运行状态，以及 Codex 原有的审批和提问；不复刻完整终端界面。

## 2. 窗口内容

一个窗口分成四块：

1. **会话区**：工作目录、选择目录、启动会话、结束会话、当前状态。
2. **输出区**：流式文本、工具执行状态、错误和自动发送记录。Codex 原有审批或提问在此呈现，不用自动发送内容代答。
3. **手动输入区**：多行输入框、发送、停止生成。停止生成保留当前会话，结束会话关闭后端进程。
4. **自动发送区**：内容、开关、策略、策略参数、随机延迟开关与范围、次数上限、保存并应用、当前连续次数和下一次发送倒计时。

发送内容为空时不能开启自动发送。工作目录必须存在。运行中的手动发送按钮不可用，输入草稿仍可编辑。

## 3. 等待时间与计数

`n` 表示本轮连续恢复中的第几次自动发送，从 1 开始。初始手动请求不计入自动发送次数。

| 策略 | 第 n 次的基础等待时间 |
| --- | --- |
| 固定间隔 | 配置的间隔秒数 |
| 指数退避 | 初始秒数 × 2^(n−1)，达到基础等待上限后保持不变 |
| 自定义间隔 | 使用列表第 n 项；超过列表长度后一直使用最后一项 |

开启随机延迟后：

`实际等待 = 基础等待 + 范围内均匀随机抽取的秒数`

随机值只在安排本次发送时抽取一次，不随界面刷新改变。范围两端均包含。指数策略的上限限制基础等待，界面明确标注“不含随机延迟”。

常规触发从该回合最终失败开始计时；保存设置或手动启用后的重新安排，从该次操作开始计时。不使用持续运行的固定频率定时器向正在执行的 Codex 插入消息。

### 默认值

以下默认值已随整体方案确认，可在界面调整：

| 参数 | 默认值 |
| --- | --- |
| 默认策略 | 固定间隔 |
| 固定间隔 | 30 秒 |
| 指数初始间隔 / 基础等待上限 | 30 秒 / 300 秒 |
| 自定义间隔 | 30、60、120 秒 |
| 随机延迟 | 默认关闭；范围初值 0～10 秒 |
| 自动发送内容 | 空，填写后才能启用 |
| 连续次数上限 | 不限，已由用户确认 |

基础间隔和序列项必须是正整数秒；随机范围允许 0，且最小值不得大于最大值；次数上限只能是不限或正整数。

## 4. 自动发送流程

主路径：

`正在执行 → 目标错误且回合最终失败 → 等待 → 向同一会话发送 → 正在执行`

正常完成后清零连续次数，等待下一次手动输入。自动发送不是任务成功后仍不断发送的定时器。

1. 读取本工具所管理会话的结构化事件。只根据该回合的最终失败原因识别目标错误，不匹配用户消息、模型回复或工具输出中的同名文字。
2. 确认没有后续回合、没有待处理审批或提问、自动发送已开启、内容有效、次数未达到上限。
3. 为该失败回合安排一个可取消的等待任务，记录会话标识和失败回合标识。
4. 等待结束后再次检查以上条件。条件仍成立，才通过会话接口发送保存好的文本。安排等待不等于已经发送。
5. 后端确认接受本次输入后，自动发送次数加一。同一失败回合只能自动发送一次；不同通知重复报告同一失败也不重复安排。
6. 如果发送是否被接受无法确定，暂停自动发送并显示连接问题，不盲目重发。

取消和暂停规则：

- 手动发送、停止生成、结束会话、关闭自动发送、退出工具，均取消尚未执行的等待任务。
- 单独关闭自动发送不打断已经开始的回合；需要打断时使用停止生成。
- 非目标错误、后端退出或连接异常，不自动套用本重试策略，暂停自动发送并显示原因。
- 达到配置的连续次数上限后暂停，不再安排下一次发送。
- 启动新会话时，旧会话的等待任务全部失效。重启不恢复旧任务。

### 补充行为

以下行为已随整体方案确认：

- **保存设置**：若正在倒计时，取消旧任务，使用新内容和新参数从保存时重新计时；未发送不增加次数。
- **开启自动发送**：当前会话若已停在目标错误上，且该失败尚未自动处理，可以开始倒计时；不扫描旧会话或历史显示内容。
- **手动发送**：取消旧的自动任务，并开始新一轮连续次数计数；仅编辑手动输入草稿不取消等待。

## 5. 技术方案

采用 **C# + .NET 10 + WPF**。本机已安装 .NET SDK 10.0.401 和 Windows Desktop Runtime 10.0.12。

通信关系：

`WPF 窗口 ↔ 本工具创建的 codex app-server 子进程 ↔ Codex 会话`

- 使用 app-server 默认的 stdio / JSONL 双向通信，不监听终端屏幕，不模拟按键，不使用剪贴板，也不开放本地 HTTP 服务。
- 使用 .NET 自带的进程、JSON、随机数和可取消延时能力。无需引入 Web 框架、通用调度系统或策略插件体系。
- 创建后端进程时不弹出控制台窗口。启动路径和参数分开处理；Windows 下 npm 安装的 Codex 启动包装需要在第一阶段验证。
- 保持一个会话，使用 `thread/start` 创建会话，`turn/start` 发送输入，读取输出及完成事件，使用 `turn/interrupt` 停止生成。
- 登录、模型、权限等沿用 Codex 原有配置。工具不复制或保存登录凭据，不自动代答审批。
- 设置保存在 `%LOCALAPPDATA%\CodexAutoContinue\settings.json`，不改写 Codex 的配置文件。

### 开发阶段核验结论

- 本机 `codex --version` 返回 `codex-cli 0.154.0`。
- 本机 `codex app-server --help` 提供 stdio 传输选项。
- 官方文档提供流式事件、同会话输入、回合最终失败和审批接口。
- 已使用本机原生 Codex 进程、隔离的 `CODEX_HOME` 和本地模拟服务完成初始化、创建会话、发送、内置重试、最终失败、自动续发及正常完成校验；未请求真实模型。
- 目标文案对应 `internalServerError`，**不是** `serverOverloaded`。同一个错误码还可能表示其他内部错误，因此不能只按错误码触发。
- 实测最终事件为 `turn/completed`，`turn.status = "failed"`，目标文案位于 `turn.error.message`。之前的 `error` 通知可能带 `willRetry = true`，不会触发续发。
- 真实进程验证结果：本地 HTTP 500 → 一次内置重试 → 目标最终失败 → 一次自动续发 → 本地成功响应。两个回合使用同一个 thread。

不能把任意 5xx、普通聊天文本或内置重试通知都当成触发条件。app-server 接口以本机 0.154.0 生成的协议及实际事件为准。

## 6. 开发阶段

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| 1. 协议验证 | 验证 Windows 启动方式、初始化、创建会话、收发消息、停止生成及审批；核对 high demand 的最终失败事件 | 确定本机可用的启动方法和触发依据；如果错误映射不能证实，不先实现自动发送 |
| 2. 单窗口客户端 | 实现目录选择、启动和结束、流式输出、手动输入、必要审批与提问、设置保存 | 能在一个窗口中完成单会话文本交互，沿用现有 Codex 配置 |
| 3. 自动发送 | 实现三种基础间隔、附加随机延迟、次数限制、去重、取消、状态和倒计时 | 只在目标最终失败后发送，不干扰运行中的回合或手动操作 |
| 4. 验证与交付 | 完成最小自动自检和 Windows 真机验收，发布可运行文件及说明 | 下列验收项通过；不制作安装器，不加入未请求功能 |

先完成协议验证，再接界面和调度逻辑。逻辑测试使用符合本机协议的构造事件，或已核验的录制事件；这不替代真实错误映射的核验，也不通过高频请求制造服务过载。

## 7. 验收清单

保留一个最小可运行自检，使用模拟事件和确定的随机取值检查策略及状态，不依赖真实服务故障。

1. 用户消息、模型回复或工具输出包含目标文案时，不触发自动发送。
2. 内置重试期间不发送；同一回合最终失败通知重复到达时，只安排一次。
3. 固定、指数上限、自定义序列耗尽后的等待正确；随机增量在范围内，每次安排只抽取一次。
4. 默认不限次数；配置上限后正确暂停；正常完成后连续次数归零。
5. 倒计时期间手动发送、停止、关闭自动发送或退出后，旧任务不能继续发送；新会话不受旧任务影响。
6. 修改并保存设置后，待发任务按确认后的新规则处理，不发送已失效的旧内容。
7. 输出持续刷新时窗口可操作；运行中不能手动发送，停止生成后可以继续同一会话。
8. 最小化时可以自动发送，不切窗口、不抢焦点、不改剪贴板；关闭时只结束本工具创建的 Codex。
9. 重开工具后设置保留，自动发送关闭，不恢复上次会话或倒计时。
10. 连接中断或发送结果不明时暂停，不盲目追加重复输入；原有审批和提问不会被自动代答。

## 11. 追加需求：绑定已有 Codex 会话

2026-09-20 用户确认：

- 按 Codex 会话名称、工作目录或 ID 选择，不依赖 Windows Terminal 页签标题。
- 只绑定共享后台中的会话。内嵌运行的会话由用户正常退出，再用原会话 ID 接入共享后台；不无缝注入既有终端进程。
- 绑定期间手动发送统一在小工具内操作。原终端保留输出、审批和提问。
- 保留已有等待策略、次数上限、最终失败触发规则、后台行为和成功通知。
- 关闭工具或断开绑定不能停止外部会话及后台。点击“停止生成”才中断当前回合。

实现使用 .NET 自带的 Unix 域套接字和 WebSocket，连接本机 Codex 默认的私有控制套接字。没有新依赖、TCP 监听端口、终端抓屏、模拟输入或剪贴板操作。沿用原 JSON-RPC 分发、重试状态机和窗口。

连接时调用 `thread/loaded/list` 和 `thread/read`，仅展示已加载且允许直接输入的主会话。绑定调用 `thread/resume`，不附带模型、目录或权限覆盖，取最近一回合摘要并缓冲绑定期间的事件。历史成功不通知；当前目标失败可在手动启用自动发送后处理。连接失败时不会另启内嵌后端或恢复历史会话冒充目标。

发送仍使用即时 `turn/start`，不使用会持久保存并自动派发的 `thread/queue/add`。发送前重新检查会话空闲状态；检测到其他客户端开始回合时暂停自动发送。这不是服务端原子比较并发送，所以同时从终端和工具发送不在支持范围内，已由用户接受统一从工具发送的约束。

共享模式仅观察审批请求，不发送批准、拒绝或“不支持”的答复。关闭连接只关闭自身 WebSocket，不发中断、卸载或后台停止请求。原有工具新建模式继续只停止自身启动的进程。

新增本机集成检查 `tests/CodexAutoContinue.Checks/SharedCheck.cs`：隔离配置、原生 Codex 共享服务、两个客户端及本地模拟模型。检查已有最终失败的绑定、名称/目录/ID 筛选、只续发一次、原 thread ID 保持、外部输入暂停、审批不被代答、断开后原客户端仍可回答审批并完成回合。单独运行使用 `--shared`；完整本机与桌面检查包含此项。

发布目录为 `dist/win-x64-shared`，不覆盖或停止正在使用的旧版。启动与原会话接入命令见 README。
